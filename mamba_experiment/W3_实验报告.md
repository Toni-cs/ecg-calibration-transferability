**一句话**：架构真的换了、600 个种子真跑完了、机制被三类证伪 + 独立 CNN 对照全部确认；但主终点形式上 **差 6 个种子没过 90% 线**，按冻结条款我不改阈值，也不做 v0.4。

## 1. 换架构换在哪（不是改文档里的名字）

| 项 | 实现 |
|---|---|
| 骨干 | **对角 selective state-space block**：input-dependent Δ/B/C、门控因果卷积 + SSM scan（Mamba-1 / S6 的对角状态近似，numpy） |
| 独立性 | **每个种子独立随机初始化 Mamba 权重**，独立采样源域/目标域波形、群温度、群规模 |
| 分类器 | 冻结的源域 ridge readout（含源域统计量标准化，部署时固定） |
| 源域 | 有标签 → 拟合 readout + NLL 网格拟合 `τ_s` + 得到 `h_ref` |
| 目标域 | **无标签** → 只用置信度直方图拟合每群 `T̂_g`（GST） |
| 标签 | 目标域标签**仅用于最终 ECE/NLL/Brier 打分** |

**logits 真的由 Mamba 前向产生**，不再是 W2 的解析高斯扰动。为让随机初始化编码器输出具备真实模型量级，readout 加了源域固定的特征标准化（等价 BN running stat，部署冻结）——没有这一步所有温度估计会撞网格边界，那是坏实验不是结果，F0 门槛会拦住。

**诚实边界**：不是官方 Mamba CUDA kernel、不是预训练权重、不是真实 ECG。合成 12 导联 toy waveform（L=48 下采样）+ 对角 SSM 近似。真实 1.15M 波形前向仍需 PhysioNet DUA。

## 2. 600 个独立种子的主结果

种子 **3000–3599**，与 W1/W2 全部种子不重叠。全部 600 个 Δ 值逐条保存于 `mamba600_results.json`，未裁剪。

| 估计器 | ECE | NLL |
|---|---|---|
| SOURCE | 0.2239 ± 0.0703 | 1.7216 |
| GLOBAL（单温度） | 0.1039 ± 0.0295 | 1.3330 |
| **GST（每群）** | **0.0791 ± 0.0190** | **1.2878** |
| SHRINK | 0.0790 ± 0.0190 | 1.2877 |
| TRUE-T（真实倍率） | 0.0820 ± 0.0214 | 1.2903 |
| ORACLE（标签上界） | 0.0670 ± 0.0151 | 1.2764 |

`ΔECE = GST − GLOBAL`：

| 指标 | 值 |
|---|---|
| **mean** | **−0.0248**（阈值 −0.020 ✅） |
| sd | 0.0255 |
| 中位 / Q25 / Q75 | −0.0192 / −0.0363 / −0.0059 |
| min / max | −0.1374 / **+0.0332** |
| **负向种子** | **534/600 = 89.0%**（要求 ≥540 = 90% ❌） |
| 跨种子 bootstrap B=10,000 | **CI [−0.0269, −0.0228]，p<0.0001** ✅ |

**F0 有效性门槛 PASS**：600/600 种子 ORACLE 的 NLL 最优；操控有效性均值 +0.1200、99.5% 种子为正（证明群温度失真确实造成可修复误校准）。

如实记录的偏差：预注册里写「ECE oracle 反转约 0.005 量级」，实际 **75/600 种子反转、最大 gap 0.0185**。原因是 ORACLE 按 NLL 拟合、ECE 是分箱估计量，两者最优温度不必重合；预注册**本就没设 ECE 门槛**，所以不影响 F0，但数字按实际报，不藏。另有 0.5% 种子操控有效性为负（min −0.0106），同样保留。

## 3. H1 为什么是 False，以及我为什么不动它

三条判据过了两条：mean −0.0248 ≤ −0.020 ✅、跨种子 CI 上界 −0.0228 < 0 ✅。**只差第三条：534 vs 540，6 个种子，0.9 个百分点。**

按 `PREREGISTRATION_W3_MAMBA600.md` §7 失败条款：

- **阈值不改**（不降到 85%、不换指标、不挑子群、不补种子）
- **不存在 v0.4**（W2 已有两轮条款修正，本轮终局）
- GST-on-Mamba **降级为探索性**；T1 主线回到 BCC 证书 + 1.15M 系统验证 + E5 问题结论

这 6 个种子不是运气问题，而是暴露了真实边界：**约 11%（66/600）的部署场景下，分群校准反而比单温度更差**，最差 +0.0332 ECE。这比硬凑一个"全绿"更有价值——它直接说明无条件 GST 不能进临床，需要门控。

## 4. 但机制被确认得很硬（这部分是真"好结果"）

**证伪检验**（独立种子 3600–3659，60 个）：

| ID | 操作 | mean ΔECE | 判定 |
|---|---|---|---|
| F-M1 | 合并所有群为 G=1 | **0.0000** | ✅ GST 严格退化为 GLOBAL |
| F-M2 | 随机置换 `group_id` | **+0.00079** | ✅ 优势消失 |
| F-M3 | 群同质 spread=0 | **−0.00139** | ✅ 优势消失 |

**架构对照**（独立种子 3700–3799，100 个，CNN-1D）：
`mean ΔECE = −0.0266`，**88/100 负向**，与 Mamba 同号、幅度接近（gap 0.0018）。结论**不依赖 Mamba 特有结构** ✅。

合计 **700 个前向种子 + 2 种架构 + 3 类证伪**，方向一致。W2 只有 60 个解析 DGP 种子；这一轮把结论从"解析构造"推进到"神经网络前向 logits"，并证明它是群结构效应而不是架构偶然。

> F-M1 精确等于 0 是个漂亮的内部一致性证明：合并群后 GST 与 GLOBAL 在数学上就是同一个优化问题。

## 5. 探索性 gate 分析（明确标注：不可作确认性证据）

按失败条款，我做了**纯描述性**分层，只用来生成下一轮假设，**绝不用于救 H1**：

| 操控强度分层 | n | mean ΔECE | 负向比例 |
|---|---|---|---|
| low | 150 | −0.0325 | 92.7% |
| mid | 300 | −0.0263 | 89.0% |
| high | 150 | −0.0141 | 85.3% |

`corr(ΔECE, 操控强度) = +0.267` —— **与直觉相反**：温度失真越强，GST 增益反而越小；66 个有害种子的平均操控强度（0.1381）还略高于有益种子（0.1178）。

**所以：简单的"用失真强度做 gate"不成立。** 这否掉了我原本想给的轻松解法。更合理的候选是 Ψ 曲线极小深度 / 群内直方图方差这类**无标签置信度**统计量，但那需要新预注册才能验证。本轮**不宣称 gate 已解决**。

## 6. 执行层面的两件事（如实记录）

1. **平台中断**：单脚本跑到证伪阶段被沙盒 502 杀掉两次，故把执行拆成 `run_w3_main.py`（600 种子）与 `run_w3_rest.py`（证伪 + CNN）。**设计、种子、阈值、估计器逐字不变**，只是执行分期。
2. **向量化加速**：把 Ψ 表与 oracle 的 241 点 Python 循环改成批量张量运算，20 种子对照验证数值完全一致（mean −0.0278、逐估计器 ECE 逐位相同），600 种子从 ~211 s 降到 156 s。**纯实现优化，不改预注册设计。**
